## From Source

```bash
git clone https://github.com/mubaidr/gem-team.git
cd gem-team

# Dry-run first to preview
apm install . --target claude,cursor --dry-run

# Real install from local path
apm install /absolute/path/to/gem-team --target claude,cursor
```

## Package Validation

```bash
# Marketplace resolution, generated metadata drift, version alignment, audit
apm run check

# Generate a distributable ZIP under build/
apm run pack
```

`apm run check` fails if `.claude-plugin/marketplace.json` is stale. After
changing `apm.yml` or package metadata, regenerate it with `apm pack`, inspect
the diff, and commit the generated marketplace file.

The canonical publishable sources are `.apm/agents/` and `.apm/skills/`.
`build/` contains generated bundles, remains ignored, and is recreated during a
release. Direct `apm install mubaidr/gem-team` does not require committed build
artifacts.

## Release Flow

1. Merge changes to `main` with a conventional commit or PR title.
2. Release Please opens or updates the release PR and bumps `apm.yml` plus
   `version.txt`.
3. Regenerate `.claude-plugin/marketplace.json` in the release PR when package
   metadata changes; `apm run check` enforces that it is reproducible.
4. Merging the release PR creates the `gem-team-v<version>` tag and GitHub
   Release.
5. The release workflow validates the tag, creates the ZIP and SHA-256 sidecar,
   and attaches versioned artifacts to the existing GitHub Release.

If asset publishing fails after Release Please has created the release, rerun
the **Publish Release Assets** workflow manually with the existing release tag.

## Agent and Skill Sources

- Agent definitions: `.apm/agents/*.agent.md`
- Packaged skills: `.apm/skills/*/SKILL.md`
- The standalone `gem-critic` agent was removed. `gem-reviewer` now uses
  independent `review_mode`, `review_target`, and `review_scope` axes.
- Plan validation uses target `plan` with scope `full`. Risk-triggered
  integration validation uses mode `high`, target `integration`, and scope
  `affected`; it is not a routine wave review.
- Critic mode is read-only and is used for requested decision challenges or
  selected plan risks. When testing it locally, set mode `critic`, the correct
  target and scope, and provide `handoff.critic_subject` plus
  `handoff.critic_context`. The source contract is in
  `.apm/agents/gem-reviewer.agent.md`.

When adding or changing a skill, keep its `name` aligned with the directory name and its description specific
enough to support task matching. Rebuild or repack the package before validating generated tool targets.

## Docs Site

The docs site lives at `docs/src/`: a Nuxt 4 app with Nuxt UI & Nuxt Content.

```bash
cd docs/src
npm install
npm run dev
```

> See [Nuxt Content docs](https://content.nuxt.com) for MDC syntax and authoring.
