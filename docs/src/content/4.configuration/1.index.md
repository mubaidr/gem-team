Configure Gem Team in `.gem-team.yaml` at the project root.

```yaml
orchestrator:
  max_concurrent_agents: 2
  git_commit_on_gate_pass: false

model_routing:
  enabled: false
  tiers:
    premium: "gpt-5.6-sol (openai)"
    explore: "gpt-5.6-luna (openai)"

quality:
  visual_regression_enabled: false
  visual_diff_threshold: 0.95
  a11y_audit_level: none

devops:
  approval_required_for: [production]
  deployment_strategy: rolling
  auto_rollback_on_failure: false

testing:
  screenshot_on_failure: true
```

See the [fully commented default](https://github.com/mubaidr/gem-team/blob/main/.gem-team.yaml).

## Settings Reference

### Model Routing

Model routing chooses a configured model for each delegated agent. Values use the `model (provider)` format.

| Qualified Setting             | Type    | Default                 | Description                                            |
| :---------------------------- | :------ | :---------------------- | :----------------------------------------------------- |
| `model_routing.enabled`       | boolean | `false`                 | Enable tier-based model selection for delegated agents |
| `model_routing.tiers.premium` | string  | `gpt-5.6-sol (openai)`  | Model used by planning, diagnosis, and review agents   |
| `model_routing.tiers.explore` | string  | `gpt-5.6-luna (openai)` | Model used by exploration and bounded execution agents |

#### Agent tiers

**Premium:** `gem-planner`, `gem-debugger`, and `gem-reviewer`.

**Explore:** `gem-researcher`, `gem-implementer`, `gem-browser-tester`,
`gem-mobile-tester`, `gem-devops`, `gem-documentation-writer`,
`gem-skill-creator`, and `gem-code-simplifier`.

The Orchestrator is not assigned a tier. With routing disabled, delegation uses the normal selection process.

Quality-check settings are defaults, not hard requirements. Task acceptance
criteria and explicit user requests take precedence over `.gem-team.yaml`;
otherwise, configured quality settings take precedence over agent defaults.

### Orchestrator

| Qualified Setting                      | Type   | Default | Description                                        |
| :------------------------------------- | :----- | :------ | :------------------------------------------------- |
| `orchestrator.max_concurrent_agents`   | number | `2`     | Maximum parallel agent executions                  |
| `orchestrator.git_commit_on_gate_pass` | bool   | `false` | Git commit wave output when an invoked gate passes |

Complexity and reviewer selection are evidence-driven workflow rules rather
than configuration switches. Phase 0 assigns provisional complexity from the
request and supplied evidence. MEDIUM/HIGH plans always receive deterministic
validation. Routine MEDIUM plans can skip independent review; explicit review
requests, validation failures, HIGH/high-risk work, and critic signals still
route to the reviewer.

The reviewer contract uses independent `review_mode`, `review_target`, and
`review_scope` axes. For critic mode, provide `critic_subject` and
`critic_context` under `handoff` as documented in [Reviewer routing](/agents#reviewer-routing).

### Quality

| Qualified Setting                   | Type    | Default | Description                                               |
| :---------------------------------- | :------ | :------ | :-------------------------------------------------------- |
| `quality.visual_regression_enabled` | boolean | `false` | Enable screenshot comparison checks                       |
| `quality.visual_diff_threshold`     | number  | `0.95`  | Visual comparison threshold from `0.0` to `1.0`           |
| `quality.a11y_audit_level`          | enum    | `none`  | Accessibility (a11y) audit depth: `none`, `basic`, `full` |

### DevOps

| Qualified Setting                 | Type    | Default        | Description                                                    |
| :-------------------------------- | :------ | :------------- | :------------------------------------------------------------- |
| `devops.approval_required_for`    | enum[]  | `[production]` | Environments that require explicit approval                    |
| `devops.deployment_strategy`      | enum    | `rolling`      | Default deployment strategy: `rolling`, `blue_green`, `canary` |
| `devops.auto_rollback_on_failure` | boolean | `false`        | Attempt rollback after deployment failure                      |

### Testing

| Qualified Setting               | Type    | Default | Description                                     |
| :------------------------------ | :------ | :------ | :---------------------------------------------- |
| `testing.screenshot_on_failure` | boolean | `true`  | Capture a screenshot when browser/UI tests fail |
