## Configuration File

Configure Gem Team in `.gem-team.yaml` at the project root. All settings are optional with sensible defaults.

### Complete Annotated `.gem-team.yaml`

```yaml
# .gem-team.yaml — Complete annotated example
# All sections are optional; omit sections you don't need to use defaults.

# -----------------------------------------------------------
# Orchestrator — Workflow execution controls
# -----------------------------------------------------------
orchestrator:
  # Maximum parallel agent executions per wave.
  # Retries consume a concurrency slot.
  # Recommended: 1-2 (solo), 2 (team), 3-4 (CI/CD).
  max_concurrent_agents: 2

  # When true, auto-commits wave output after review gate passes.
  # Commit message format: wave({n}): {objective}
  git_commit_on_gate_pass: false

# -----------------------------------------------------------
# Model Routing — Tier-based model selection for delegated agents
# -----------------------------------------------------------
model_routing:
  # Enable tier-based model selection. Disabled by default.
  # Orchestrator always uses the session default model.
  enabled: true

  tiers:
    # Premium tier: reasoning-heavy agents (Planner, Debugger, Reviewer)
    premium: "claude-4 (anthropic)"

    # Explore tier: fast execution agents (Implementer, Testers, DevOps, etc.)
    explore: "claude-3.5-haiku (anthropic)"

# -----------------------------------------------------------
# Quality — Visual regression, accessibility, security gates
# -----------------------------------------------------------
quality:
  # Enable screenshot comparison on UI changes
  visual_regression_enabled: true

  # Visual comparison threshold (0.0 = lenient, 1.0 = pixel-perfect)
  # 0.99 = design systems, 0.95 = general UI, 0.90 = dynamic content
  visual_diff_threshold: 0.95

  # Accessibility audit depth: none | basic | full
  # basic: contrast, ARIA, focus, touch targets
  # full: all basic + reduced motion, semantic HTML, screen reader, keyboard
  a11y_audit_level: basic

# -----------------------------------------------------------
# DevOps — Deployment strategies, approval gates, rollback
# -----------------------------------------------------------
devops:
  # Environments requiring explicit approval before deployment
  approval_required_for: [production]

  # Deployment strategy: rolling | blue_green | canary
  # blue_green/canary enable instant rollback
  deployment_strategy: blue_green

  # Attempt automatic rollback on health check failure
  auto_rollback_on_failure: true

# -----------------------------------------------------------
# Testing — Test execution behavior
# -----------------------------------------------------------
testing:
  # Capture screenshot when browser/UI tests fail
  screenshot_on_failure: true
```

## Settings Categories

| Category | Purpose | Key Settings |
|----------|---------|--------------|
| **[Model Routing](/configuration/model-routing)** | Tier-based model selection for delegated agents | `enabled`, `tiers.premium`, `tiers.explore` |
| **[Orchestrator](/configuration/orchestrator)** | Workflow execution controls | `max_concurrent_agents`, `git_commit_on_gate_pass` |

## Priority Order

Settings precedence (highest to lowest):

1. **Task acceptance criteria** — Explicit criteria in task definition
2. **Explicit user requests** — Direct instructions in task
3. **`.gem-team.yaml`** — Project configuration
4. **Agent defaults** — Built-in agent defaults

---

## Configuration Scenarios

| Scenario | Key Settings | Why |
|----------|-------------|-----|
| Team project | Model routing + blue_green + basic a11y | Balanced quality and cost |
| Solo developer | No routing, no gates, concurrency 3 | Minimal overhead |
| CI/CD | Concurrency 4 + canary + full a11y | Maximum automation |
| High-security | Concurrency 1 + dual gates + strictest quality | Maximum review |
| Mobile-first | Full a11y + canary + device screenshots | Mobile-specific needs |
