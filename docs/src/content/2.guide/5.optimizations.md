Cost and performance are core design principles. This page covers agent execution and context management.

## Agent Execution Optimization

See [Agents ->](/agents) for model routing recommendations.

### Output Hygiene

Agents minimize token waste through:

- **Native tool flags**: Agents use `--quiet`, `--oneline`, `maxResults` to truncate output at source
- **Pipeline truncation**: `head`/`tail`/`grep` used only when native flags are insufficient
- **Context pruning**: Execution agents receive only authoritative `task_definition` scope with nested `handoff`; the planner receives a bounded `planning_context` rather than rediscovering the repository; the reviewer uses a dedicated review `handoff`; every delegate gets a sanitized, role-scoped `config_snapshot`
- **Proportional architecture**: YAGNI/KISS keeps plans focused on the smallest architecture, specialist set, wave sequence, and validation path that satisfy the baseline
- **Minimal result contracts**: Agents return only workflow state, failure classification, role-specific evidence, and actionable downstream handoffs
- **Evidence by reference**: Detailed logs, traces, screenshots, and reports stay in task-scoped artifacts; results return only an evidence path or manifest
- **Conditional learning**: `learn` is returned only for stable, reusable, repeated, or persistent findings. After final success, promote it when confidence is at least 0.95.

## Handoff Optimization

> Handoff scope and memory tiers are covered in [Core Concepts ->](/guide/core-concepts).

Execution agents receive scope through `task_definition.handoff` (nested inside each task). The Planner receives a bounded `planning_context` with only objective-aligned clarifications and sufficient discovery, and may request more context only for a concrete blocker. Relay only relevant evidence, and promote stable learnings after final success at confidence 0.95 or higher.
