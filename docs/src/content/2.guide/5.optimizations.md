Cost and performance are core design principles. This page covers agent execution and context management.

## Agent Execution Optimization

See [Agents ->](/agents) for model routing recommendations.

### Output Hygiene

Agents minimize token waste through:

- **Native tool flags**: Agents use `--quiet`, `--oneline`, `maxResults` to truncate output at source
- **Pipeline truncation**: `head`/`tail`/`grep` used only when native flags are insufficient
- **Context pruning**: Execution agents receive only authoritative `task_definition` scope; planner and reviewer use dedicated handoffs, and every delegate gets a sanitized, role-scoped `config_snapshot`
- **Minimal result contracts**: Agents return only workflow state, failure classification, role-specific evidence, and actionable downstream handoffs
- **Evidence by reference**: Detailed logs, traces, screenshots, and reports stay in task-scoped artifacts; results return only an evidence path or manifest
- **Opt-in learning**: `learn` is not universal. Agents return durable learning only when explicitly requested and when it is reusable

## Context & Cache Optimization

> Plan context structure and memory tiers are covered in [Core Concepts ->](/guide/core-concepts). This section covers eviction and efficiency settings.

Execution agents receive scope through `task_definition.handoff`; planner and reviewer use dedicated handoffs. Relay only relevant evidence, and promote stable learnings after final success at confidence 0.95 or higher.
